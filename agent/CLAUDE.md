# JobAgent

## Objective

Autonomous, multi-user job search agent. Scrapes job boards, filters, parses with LLM, scores fit against each user's CV, and sends daily email digests. New users onboard via `python onboard.py --cv path/to/cv.docx`.

## Current State

All phases through onboarding are complete and live:
- **Scrape → Prefilter → Parse → Heuristic rank → RAG score → Email digest** — end-to-end pipeline working
- **Scoring**: gpt-4o-mini for parsing, gpt-4o for RAG scoring. Post-parse heuristic gate skips scoring for clear misses.
- **Email digest**: Gmail SMTP + Jinja2 template. `--notify` flag on main.py.
- **GitHub Actions**: daily cron at 07:00 CET weekdays. Secrets: `OPENAI_API_KEY`, `GMAIL_ADDRESS`, `GMAIL_APP_PASSWORD`, `NOTIFY_EMAIL`.
- **Gap tracking**: gap_tracker.py persists scored job gap/strength data to data/gap_history/ (JSONL, 90-day retention).
- **Onboarding**: `python onboard.py --cv cv.docx` — .docx → profile YAML + knowledge/cv.md in one command.

## Architecture

```
JobSpy + ATS watchlist + WTTJ → Dedup → Prefilter → LLM Parse → Heuristic gate → RAG Score → Email
                                          (lang detect)  (gpt-4o-mini)  (cost gate)   (gpt-4o)
```

## Key Invariants

- **Dedup**: always use `make_job_id()` from scraper.py. Never create alternative ID functions.
- **Seniority weights**: never stored in YAML. Computed at load time from `target.level` + `target.track` by `user_config.compute_seniority_weights()`.
- **Prompts**: never inline in Python. Source of truth is `prompts/*.md`, read at runtime via cached loader.
- **Tier thresholds**: A ≥ 50, B 30–49, C < 30. Consistent across scorer, notifier, digest.
- **Heuristic gate**: jobs below `scoring.rag_threshold` or with salary < `scoring.salary_min` skip RAG scoring; appear in digest with heuristic score.
- **knowledge/ is read-only**: never modify files there. onboard.py writes cv.md once at onboarding.

## Parser Schema — v1.1 (2026-02-23)

`must_have_skills` is now **technical-only** (tools, platforms, frameworks). Soft skills, years of experience, and education requirements moved to new field `experience_requirements`.

| Field | v1.0 | v1.1 |
|---|---|---|
| `must_have_skills` | "hard requirements explicitly stated" — mixed soft+tech | ONLY specific technical tools/platforms (SQL, Python, dbt…) |
| `experience_requirements` | *(did not exist)* | Years of experience, domain background, education, soft skills |
| `technical_stack` | unchanged | unchanged |

**Impact**: `key_tools` extraction in jobseeker's `api/cv/plan.py` is more accurate because `must_have_skills` no longer pollutes the tool list with "5+ years PM experience". Heuristic skill matching in `_heuristic_score()` is also cleaner.

**Files changed**: `prompts/parser-prompt.md` (version → v1.1), `schemas/parsed_job.json`

## Multi-User Scoring

- Scoring parameterized for multi-user: role_type, geography, adjacent domains derived from profile. No hardcoded personal values in scorer.py, main.py, notifier.py, or prefilter.py.
- Per-profile searches, watchlist, prefilter preferences. Each profile points to its own config files; fallback to shared config if field absent.
- 72 tests covering regression, parameterization, home locations, per-profile config loading, and end-to-end non-Juan scoring.

## Developer Experience

This repo uses a 3-level LLM-friendly DX system:
- **Level 1**: This file (CLAUDE.md) + `.claude/rules/` — universal context
- **Level 2**: `patterns/` (interface contracts), `prompts/` (versioned business logic), `docs/decisions/` (ADRs)
- **Level 3**: `verify.py` (planned, not yet needed at current repo size)

For detailed module contracts, read the relevant file in `patterns/` before implementing.
Architectural decisions and trade-offs are in `docs/decisions/*.md`.
